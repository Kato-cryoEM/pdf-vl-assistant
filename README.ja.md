# PDF VL Assistant

英語の論文 PDF を、**ローカルの視覚対応 LLM** でページごとに読み解き、日本語訳と原文を左右に並べて読むためのツールです。外部サービスには一切送りません。

［[English](README.md)］

## できること

- **ページ画像を LLM に見せて解析** — 文字だけでなくレイアウトを見るので、段組み・脚注・行番号に強い
- **文単位の対訳** — 訳文にカーソルを合わせると、原文 PDF の該当箇所が光る
- **図・表をクリックで表示** — 本文中の「Fig. 3」「Table 2」を押すと、その図表と**和訳済みキャプション**が出る
  - 写真だけでなく**ベクター図**（グラフ・模式図）も切り出す
  - 2 段組でも、図の実体に合わせて切り出すので隣の段が混ざらない
  - **複数ページに跨る表**は 1 枚に繋げる
  - 図が 1 ページを占め legend が次ページにある組版にも対応
- **数式はそのまま画像で表示** — 文字として取り出すと項ごとにバラバラになるため、元ページから切り出して貼る
- **サプリメンタル PDF の追加解析** — 本編と番号空間を分け、「Supplementary Fig. 2」から正しく引ける
- **解析中でも読める** — 終わったページから順に表示。中断・再開・ブラウザのリロードに耐える
- **文へのコメント** — 気になった文にメモを残せる（ディスク保存）
- **要約・質問** — 読み込んだ内容について AI に尋ねられる（後述）

## 翻訳だけでなく、読み込んだ内容を AI に尋ねられます

画面下部のチャットから、文書の内容について自由に質問できます。

- **範囲を選べます** — 全ページ、または現在のページのみ
- **要約** — 「この論文の要旨を 5 行でまとめて」「この節の主張と根拠を整理して」のように頼めます
- **続けて質問できます** — 直近 4 往復の会話を覚えているので、「それをもっと詳しく」「2 つ目はどういう意味？」のように続けて尋ねられます。古い会話は自動で忘れ、「🔄 会話をリセット」で翻訳した直後の状態に戻せます
- **答えの根拠が辿れます** — 回答中の `[P3S12]` のような引用マーカーをクリックすると、その 3 ページ目 12 番目の文へ飛び、原文と訳文の両方がハイライトされます。どこを読んでそう答えたのかを確認できます
- **Web 検索の併用**（任意）— 前提知識が要る質問では、検索結果を補助情報として使えます。オフにすれば通信は一切発生しません

## 査読（peer review）原稿にも使えます

出版社から依頼される査読原稿は、**第三者に渡してはいけない未公開の機密文書**です。クラウドの AI サービスに投げることは、多くの場合その約束に反します。

このツールは**解析も翻訳も質問もすべて手元のマシンで完結し、原稿が外に出ません**（Web 検索をオンにしたときだけ、入力した質問文が検索サービスに送られます。既定はオフです）。そのため査読原稿を安心して読み込めます。

査読作業ではこう使えます。

1. 査読原稿を取り込み、対訳で内容を把握する
2. 気になった箇所に**コメントを残す**（右クリック →「コメントを追加」）
3. チャットで「この論文の新規性は何か」「実験の対照群は妥当か」「主張に対して根拠が不足している箇所を挙げて」などを尋ね、**査読コメントの下書きを作る**
4. 回答の引用マーカーから原文に戻り、指摘が正しいか自分で確かめる

AI の回答をそのまま提出するのではなく、**見落としを減らし、下書きを作る道具**として使うことを想定しています。最終的な判断と文責は査読者にあります。なお、査読での生成 AI の利用可否は出版社ごとに方針が異なります。ローカル実行であっても、依頼元の規定を確認してください。

## 訳文の言語

既定は日本語ですが、解析開始時に**訳す言語**を選べます。日本語・English・中文（简体）・한국어・Deutsch・Français・Español に対応しています。選んだ言語はブラウザに保存され、次回も引き継がれます。言語は文書ごとに記録されるので、別の言語で解析した文書を開けば、その言語で表示されます。

質問チャットの回答も、その文書を訳した言語で返ります。

**画面の文字も選んだ言語に変わります。** ボタン・メニュー・メッセージなど約 140 種の文字列が各言語に対応しています（訳文パネルと PDF の中身は文書そのものなので対象外です）。

## 必要なもの

- Python 3.10 以上
- GPU 推奨（CPU でも動きますが、かなり遅くなります）
- モデル用のディスク空き容量（2.3GB〜。大きいモデルほど訳が良くなります）

## インストール

```bash
git clone https://github.com/Kato-cryoEM/pdf-vl-assistant.git
cd pdf-vl-assistant
./install.sh
```

`install.sh` がやること:

1. `.venv` を作り、依存パッケージを入れる
2. `llama.cpp` を用意する（配布バイナリがあればそれを使い、無ければソースからビルド。CUDA / Metal は自動判定）

GPU を確実に使いたい場合は `FORCE_BUILD=1 ./install.sh` でソースビルドを強制してください。
既に `llama-server` が入っている場合はそれを使います。

## 使い方

```bash
./run.sh
```

ブラウザで `http://localhost:8090` を開きます（同じ LAN の他の端末からも見られます）。

**初回はモデルの用意から。** 右上の「🧠 モデル管理」を押すと、

- 今つながっている LLM の状態
- このマシンに入っている GGUF（視覚対応かどうかも表示）
- 追加できる推奨モデルの一覧

が出ます。推奨リストから 1 つ選んで「ダウンロード」を押すと取得が始まり、終わったら「起動」で使えるようになります。

| モデル | 容量 | 目安メモリ |
|---|---|---|
| Qwen3.5 2B | 2.0GB | 6GB |
| Qwen3.5 4B | 3.4GB | 8GB |
| Qwen3.5 9B | 6.6GB | 12GB |
| Gemma 4 12B | 7.3GB | 14GB |
| Qwen3.5 27B | 17.7GB | 24GB |
| Qwen3.8 27B | 19.9GB | 26GB |
| Qwen3.5 35B-A3B (MoE) | 22.9GB | 30GB |
| Qwen3.8 Flash-Next (MoE 125B) | 90.9GB | 100GB |

モデルが動いたら、PDF を選んで「解析開始」を押します。1 ページ目はおよそ 1 分で読めるようになり、あとは終わったページから順に増えていきます。

サプリメンタル PDF は、本編の解析後に「📎 サプリ追加」から入れてください。

## 設定（環境変数）

| 変数 | 既定 | 意味 |
|---|---|---|
| `PORT` | `8090` | Web UI のポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス。自分だけで使うなら `127.0.0.1` |
| `LLM_URL` | `http://127.0.0.1:8004` | 既に動かしている llama-server に繋ぐ場合 |
| `PDFVL_MODEL` | — | 既定のモデル名 |
| `PDFVL_MODELS_DIR` | `./models` | モデルの置き場所 |
| `LLAMA_SERVER_BIN` | — | `llama-server` の場所を明示する |
| `PAGE_ANALYSIS` | `combined` | `combined`: 文の切れ目とページ構造を 1 ページ 1 回の LLM 呼び出しで判定する（ページ画像の読み込みが 1 回で済む）。`separate`: 2 回に分ける |
| `SENT_SPLIT_MODE` | `join` | `PAGE_ANALYSIS=separate` の時の文境界検出。`join`: 候補の切れ目のうち区切りでないものだけを答えさせる。`copy`: 本文を `|` 入りで書き写させる（遅い） |

## データの置き場所

- `jobs/<id>/` — 解析結果（ページ画像・訳文・図表・コメント）。`state.json` に入っていて、再起動しても残ります
- `models/` — ダウンロードしたモデル

どちらも `.gitignore` 済みです。

## 仕組み

1. PyMuPDF で 1 ページずつ、文字・座標・書体を取り出す
2. 文の切れ目になりうる所で本文を切っておき、ページ画像と合わせて 1 回 LLM に渡す。LLM は、切れ目でない所（Fig.・et al.・イニシャルなど）と、除くべきヘッダ・フッタ、繋ぐべき段落だけを答える。見出し・キャプション・本文の区別は書体とキーワードで付ける
3. 段落ごとに翻訳する。ページを跨ぐ文は繋いでから訳す
4. 図・表・数式は、座標から元ページの該当領域を切り出して画像にする
5. 結果を逐次ブラウザへ流す（SSE）

## 開発用

`check.py` は文の切れ目の判定を確認するための小さな別サーバーです（`python check.py` → `http://localhost:8081`）。本体の動作には不要です。
